# CLAUDE.md

Платформа для репетиторов иностранных языков: курсы и уроки, живые уроки с синхронизацией, домашка с автопроверкой, словарь и тренажёр слов.
Полное ТЗ — в `SPEC.md`. Перед любой задачей сверяйся с ним. Текущий этап разработки указан ниже.

**Текущий этап:** Этап 2 — Классы и живой урок (шаг 2.3 — сохранение ответов ученика)

## Владелец проекта
Владелец — репетитор, не программист. Поэтому:
- объясняй, что сделал, простыми словами, без жаргона;
- если нужно действие от владельца (создать аккаунт, добавить ключ, нажать что-то в Supabase/Vercel) — дай пошаговую инструкцию;
- если задача неясная или противоречит SPEC.md — спроси, а не угадывай;
- в конце задачи пиши, как проверить результат руками.

## Стек
- Next.js (App Router) + TypeScript (strict)
- Tailwind CSS + shadcn/ui, иконки lucide-react
- Supabase: PostgreSQL, Auth, Storage, Realtime
- next-intl (языки: ru, en, kk)
- dnd-kit (перетаскивание), Tiptap (редактор текста), ts-fsrs (интервальное повторение)
- Vitest, Playwright
- Деплой: Vercel

Не добавляй новые крупные библиотеки без объяснения, зачем они нужны.

## Правила
1. **Безопасность**
   - RLS включён на каждой таблице, с политиками для учителя и ученика. Новая таблица = новые политики в той же миграции.
   - Правильные ответы (`answer_key`) никогда не отправляются ученику до ответа. Проверка ответов только на сервере.
   - Секреты только в `.env.local`, никогда не коммить. Пример переменных — в `.env.example`.
   - `service_role` ключ Supabase — только в серверном коде.
2. **База данных:** все изменения схемы через миграции в `supabase/migrations/`. После изменения схемы генерируй типы TypeScript.
3. **Тексты интерфейса:** никакого текста прямо в компонентах — только через next-intl, с переводом сразу на ru, en и kk.
4. **UI:** просто и дружелюбно, минимум кнопок на экране, второстепенное прячь в меню «…». Адаптивно (телефон обязателен для ученика). Используй компоненты shadcn/ui, не изобретай свои стили без причины.
5. **Real-time:** обрабатывай потерю соединения: переподключение, восстановление состояния, индикатор «нет связи».
6. **Автосохранение** в конструкторе и в ответах ученика.
7. **Типы упражнений** реализуются по единому интерфейсу (редактор, просмотр для ученика, проверка ответа), чтобы новый тип добавлялся в одном месте.
8. **Маленькие шаги:** одна задача — одна понятная функция. После каждой задачи проект должен собираться (`npm run build`) и проходить lint и тесты.
9. Пиши тесты на логику проверки ответов и на FSRS.

## Структура (ориентир)
```
src/app/[locale]/...     страницы
src/components/ui/       shadcn
src/components/...       компоненты по фичам
src/features/exercises/  типы упражнений (по папке на тип)
src/lib/supabase/        клиенты Supabase
src/lib/...              утилиты
messages/{ru,en,kk}.json переводы
supabase/migrations/     миграции
```

## Команды
- `npm run dev` — локальный запуск
- `npm run build` — сборка
- `npm run lint` — проверка кода
- `npm test` — тесты
